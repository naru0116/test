# ふたりのやりたいことリスト（仮）開発計画書

LINE の中で開いて使える、カップル向けの「やりたいことリスト ＋ 思い出アルバム ＋ 旅のしおり」アプリの計画です。
**費用は0円**で作って運用することを前提にしています。

> この計画書の作成日は 2026-11-06 です。LINE や各サービスの無料枠・規約は変わることがあるので、着手するときに「12. 着手前に確認すること」を見直してください。

---

## 0. 結論（3行まとめ）

1. **LINE の中で動かせます。** LINE の「LIFF（LINE Front-end Framework）」／「LINE ミニアプリ」を使うと、Web で作ったアプリを LINE のトーク画面からそのまま開けます。インストール不要で、登録も利用も無料です。
2. **完全無料の構成**は「GitHub Pages（画面）＋ Supabase（データ・写真・ログイン処理）＋ LINE（ログイン・共有・通知）」です。今の別班ボードゲームと同じく、クレジットカードの登録は不要です。
3. **作る順番**は「リスト共有 → 達成して思い出化 → アルバムとスライドショー → 旅ルート風のしおり → 通知」です。最初の2つ（約2〜3週間）だけで、ふたりで使い始められます。

---

## 1. コンセプト

> 「やりたいね」を、ふたりで集めて、叶えて、思い出に残す。

アプリでは、ひとつの「やりたいこと」が次のように育っていきます。

```
 💭 いつか          📝 計画中           📅 予定あり          ✨ 叶った！         📖 思い出
 「やりたいね」 ──▶ しおりを作る ──▶ 日付が決まる ──▶ 写真・ひとこと ──▶ アルバム・
  を追加                                               を残す            スライドショー
```

ほかのアプリとの違い（重視すること）は次の3つです。

- **思い出が主役**: 叶えたあとに写真とふたりのひとことを残すと、自動で「思い出カード」になります。
- **計画は旅ルートで**: 綿密に計画するときは、立ち寄る場所を**路線図のように駅でつなぐ**しおりにします。今のボードゲームのスマホ版路線図と同じ見せ方です。
- **LINE で完結**: 相手の招待、しおりの共有、リマインドを、すべていつもの LINE の中で行えます。

## 2. LINE の中で動かす方法

### 2-1. 方式の比較

| 方式 | 中身 | 費用 | 審査 | 判定 |
|---|---|---|---|---|
| **LIFF / LINE ミニアプリ** | Web アプリを LINE 内のブラウザで開く。LINE のログイン情報やプロフィール、トークへの共有が使える | 無料 | 未認証のままなら不要 | ◎ **採用** |
| LINE 公式アカウントの Bot だけ | トークで「追加: 〇〇」と送って記録する | 無料（送信数に上限あり） | 不要 | △ 写真や地図の見せ方に向かない |
| ネイティブアプリ（App Store など） | — | Apple の開発者登録が年 12,980円前後 | 必要 | ✕ 無料にならない |

### 2-2. LIFF と LINE ミニアプリの関係

- LINE は LIFF を LINE ミニアプリに統合する予定を発表しており、公式ドキュメントでは「新しく作るなら LINE ミニアプリとして作る」ことを推奨しています。
- 中身の作り方（LIFF SDK を使う Web アプリ）はどちらも同じです。そのため **「LINE ミニアプリのチャネルで、LIFF SDK を使って作る」** 方針にします。
- 審査を通していない「未認証ミニアプリ」でも、自分たちで URL を開いて使うことはできる見込みです。ただし公開範囲（検索に出るか、誰が開けるかなど）は、作成時に公式仕様で確認します（→12章）。うまくいかない場合でも、従来の「LINE ログインチャネル ＋ LIFF」に切り替えられ、コードはほぼ同じまま使えます。

### 2-3. LINE で使う機能

| LINE の機能 | 何に使うか | 費用 |
|---|---|---|
| `liff.init` / `liff.getIDToken` | 自動ログイン（パスワード不要） | 無料 |
| `liff.getProfile` | アイコンと名前を表示 | 無料 |
| `liff.shareTargetPicker` | 相手への招待、しおり・思い出カードを**トークに送る**（自分のアカウントから送るので Bot の通数を使わない見込み） | 無料 |
| `liff.scanCodeV2` | 招待 QR を読み取る（予備） | 無料 |
| Messaging API（公式アカウント） | 「明日はデートの日！」「1年前の今日」などのリマインド | 無料枠内（コミュニケーションプランは月の送信数に上限あり。2人で使うなら十分） |

LINE の外（普通のブラウザやホーム画面に追加した PWA）でも開けるようにしておきます。LINE が使えない状況でもアルバムを見られるようにするためです。

## 3. 機能一覧

優先度は ★3（最初に作る）〜 ★1（いつか）です。

### A. ふたりの空間（ペアリング） ★3
- 最初に開いた人が「ふたりの空間」を作り、`shareTargetPicker` で相手に招待リンクを送ります。相手がそれを開くとペア成立です。
- 付き合った日を登録し、「付き合って 〇〇日」を表示します。
- 1つのデータは「ふたりの空間」に所属し、ほかの人からは見えません。

### B. やりたいことリスト ★3
- 項目: タイトル、カテゴリ（🍽 グルメ／✈ 旅行／🎡 おでかけ／🏠 おうち／🎁 記念日／🎯 チャレンジ）、メモ、参考URL、場所、だいたいの予算、いつ頃（季節・月）。
- **「わたしもやりたい」ボタン**: 相手が追加した項目に反応できます。ふたりとも押した項目には「💞 ふたりの本命」バッジが付きます。
- 状態: 💭 いつか → 📝 計画中 → 📅 予定あり → ✨ 叶った。
- 並べ替えと絞り込み: カテゴリ、状態、季節、追加した人。
- **ガチャ「今日なにする？」** ★2: 条件（おうち・予算3千円以内など）に合う項目を1つランダムに提案します。
- 達成率の表示: 「100個のうち 23個 叶えた！」。

### C. 叶えた！→ 思い出 ★3
- 「叶った」にすると、思い出の記録画面に進みます。
  - 写真（複数枚）、日付、場所。
  - **ふたりそれぞれのひとこと**（相手の分は自分が書くまで隠しておくと、見せ合う楽しみが生まれます） ★2。
  - 満足度（⭐1〜5）、「また行きたい」チェック。
- 写真はスマホの中で縮小してから保存します（長い辺1600px・WebP 形式、約200〜300KB）。無料枠を長く使うためです。

### D. 思い出アルバム ★3
- **タイムライン**: 叶えた日の順に、思い出カードを縦に並べます。
- **カレンダー表示** ★2 と **地図表示**（行った場所にピンを立てる） ★2。
- 「1年前の今日」の思い出を表示します ★2。

### E. スライドショー ★2
- 選んだ思い出（例: 「2026年の思い出」「沖縄旅行」）から、自動でスライドショーを作ります。
  - 写真がゆっくり拡大・移動する演出（ケン・バーンズ効果）、日付と一言のテロップ、表紙とエンドロール（「叶えたこと 23個」など）。
  - BGM は、ボードゲームと同じく Web Audio で端末の中で合成するオリジナル曲にします。著作権の心配がなく、通信も不要です。
- **動画で保存** ★1: `MediaRecorder` で動画に書き出します。LINE 内のブラウザでは使えない場合があるため、その場合は「ブラウザで開く」に誘導します。
- 記念日や1年の終わりに「今年のふたり」スライドショーを自動で用意します ★1。

### F. 旅ルート風しおり ★2（綿密に計画するとき）
やりたいことを「計画中」にすると、しおりを作れます。

- **路線図ビュー（メイン画面）**: 立ち寄る場所を「駅」、移動を「線路」として、上から下へ1本の路線のように並べます。
  - 駅: 時刻、場所名、やること、予約の有無、費用、メモ、写真の予定。
  - 線路: 移動手段（🚃 電車／🚗 車／🚶 徒歩／✈ 飛行機）と所要時間。線の色や種類が手段で変わります。
  - 複数日の旅行は「1日目線」「2日目線」と路線を分け、宿を乗換駅のように表示します。
  - 駅を長押ししてドラッグすると順番を入れ替えられます（ボードゲームのドラッグ操作を応用）。
- **地図ビュー**: 同じ駅を地図上に番号付きピンで表示し、順番に線でつなぎます。
- **「Google マップで経路を見る」ボタン**: 駅を経由地にしたルート URL を作って開きます（API キー不要・無料）。実際の乗換案内はそちらで確認します。
- **持ち物チェックリスト**（ふたりで共有し、どちらがチェックしたかも表示）、**予算の合計と割り勘**の計算 ★1。
- **しおりの共有**: 「しおりを LINE で送る」で、表紙カード（Flex メッセージ）をトークに送ります。読み取り専用のリンクも作れます（友達と行く旅行用） ★1。
- **印刷用レイアウト**: 紙のしおりのような A5 縦レイアウトで印刷・PDF 保存できます ★1。
- **旅が終わったら**: しおりの各駅に写真を追加すると、そのまま「旅の思い出（ルート付き）」になります。計画と思い出がつながるのが、このアプリの一番の見どころです。

画面のイメージ（スマホ縦）:

```
┌──────────────────────────┐
│ ✈ 金沢 1泊2日   🗺 地図 │
│ 1日目線 ━━━━━━━━━━━━━━  │
│                          │
│  ◉ 09:12 金沢駅          │
│  ┃  🚌 バス 15分          │
│  ◉ 09:40 ひがし茶屋街    │
│  ┃  金箔ソフト食べる 💞   │
│  ┃  🚶 徒歩 10分          │
│  ◉ 11:30 近江町市場      │
│  ┃  海鮮丼（¥3,000）     │
│  ┃  🚌 バス 20分          │
│  ◎ 15:00 宿 ── 乗換 ──▶ │
│        2日目線へ          │
│                          │
│ [Googleマップで経路] [共有]│
└──────────────────────────┘
```

### G. 通知（LINE 公式アカウント） ★1
- 予定日の前日、記念日、「1年前の今日」の思い出をお知らせします。
- 送信数の上限を超えないよう、**1日1回まとめて送る**・**ふたりで月100通まで**のように、アプリ側で制限をかけます。

## 4. 画面構成

画面下に5つのタブを置きます。

```
[ 📋 リスト ] [ 🗺 しおり ] [ ＋ ] [ 📖 思い出 ] [ 💞 ふたり ]
```

| タブ | 内容 |
|---|---|
| 📋 リスト | やりたいことの一覧、絞り込み、ガチャ |
| 🗺 しおり | 計画中・予定ありのしおり一覧 → 路線図ビュー／地図ビュー |
| ＋ | やりたいことを追加（URL を貼ると、タイトルと画像を自動で取得 ★1） |
| 📖 思い出 | タイムライン／カレンダー／地図、スライドショー |
| 💞 ふたり | 〇〇日カウンター、達成率、記念日、設定、招待 |

デザインはやわらかい配色にし、ライトとダークの両方に対応します。アイコン用のイラストはオリジナルで作ります。

## 5. 技術構成（すべて無料）

```
  ┌────────── LINE アプリ ──────────┐
  │  トーク画面 ─ リンク ─▶ LIFF ブラウザ │
  └───────────────┬──────────────────┘
                  │ ① 画面を読み込む
                  ▼
     GitHub Pages（HTML / CSS / JS・PWA）
                  │ ② LINE の ID トークンを渡す
                  ▼
  ┌──────────── Supabase（無料プラン）────────────┐
  │ Edge Function「line-login」                    │
  │   └ LINE の検証 API で ID トークンを確認 → ログイン発行 │
  │ Postgres DB（リスト・思い出・しおり）＋ 行単位の権限（RLS）│
  │ Storage（写真・非公開バケット・署名付きURLで表示）      │
  │ Realtime（相手の追加・チェックをすぐ反映）              │
  │ Edge Function「notify」＋ 定期実行 → Messaging API   │
  └───────────────────────────────────────────────┘
     地図: Leaflet ＋ OpenStreetMap（無料・キー不要）
```

### 5-1. それぞれを選んだ理由

| 役割 | 採用 | 理由 | 見送った案 |
|---|---|---|---|
| 画面の公開 | **GitHub Pages** | 今の別班ボードゲームで使い慣れている。HTTPS 付きで無料（LIFF には HTTPS が必須） | Cloudflare Pages（これも可） |
| データ・写真・ログイン | **Supabase 無料プラン** | DB・ファイル保存・サーバー処理が、カード登録なしで全部無料。SQL で「ふたり以外は読めない」権限を確実に設定できる | **Firebase**: 写真の保存（Cloud Storage）と、LINE ログインに必要なサーバー処理（Cloud Functions）を使うには、カード登録が必要な従量課金プランが必要。<br>**Cloudflare R2**: 10GB まで無料だが、カード登録が必要 |
| 地図 | **Leaflet ＋ OpenStreetMap** | API キー不要で無料 | Google Maps API（カード登録が必要） |
| 経路案内 | **Google マップの URL を開くだけ** | API を使わないので無料。乗換案内の精度も高い | 経路検索 API（有料、または利用制限が厳しい） |
| 地名から位置を探す | Nominatim（OSM） | 無料。ただし1秒1回まで。入力のたびではなく「検索」ボタンを押したときだけ呼ぶ | — |

### 5-2. コードの作り方
- 今のボードゲームと同じ**ビルド不要の ES モジュール（素の JavaScript）**で作ります。慣れた形で、GitHub に push するだけで公開できます。
  - 画面の量が増えてきたら、Vite ＋ TypeScript への移行を検討します（GitHub Actions でビルドしても無料です）。
- 外部ライブラリは CDN から読み込みます: `@line/liff`、`@supabase/supabase-js`、`leaflet`。
- 自動テスト（`node --test`）は、状態の変化（いつか→叶った）、割り勘の計算、しおりの時刻計算などのロジックに付けます。
- **リポジトリは新しく分けることをおすすめします**（例: `naru0116/futari-list`）。ボードゲームと更新のタイミングが別になり、GitHub Pages の URL もアプリ専用になります。この計画書は、そこに移すまでの仮置きです。

### 5-3. ログインの流れ
1. LINE からアプリを開くと、`liff.init()` で自動的に LINE ログインします。
2. `liff.getIDToken()` で取得した ID トークンを、Supabase の Edge Function `line-login` に送ります。
3. Edge Function は LINE の検証 API（`https://api.line.me/oauth2/v2.1/verify`）でトークンが本物か確認し、LINE のユーザー ID に対応する Supabase のユーザーを作成または取得して、ログイン状態を発行します。
4. それ以降は、Supabase の権限ルール（RLS）で「自分が所属するふたりの空間のデータだけ」読み書きできるようにします。

> ボードゲームでは、身内用と割り切って「ブラウザ側にデータが見えてもよい」設計にしていました。今回は**恋人同士の写真という大切な個人情報を扱う**ので、サーバー側の権限チェックを必ず入れます。ここが一番大きな設計上の違いです。

## 6. データ設計（概要）

```
users          : id, line_user_id, display_name, avatar_url
couples        : id, name, anniversary_date, invite_code, created_at
couple_members : couple_id, user_id, joined_at            ← ふたり（最大2人）
wishes         : id, couple_id, title, category, memo, url, place_name, lat, lng,
                 budget, season, status(someday/planning/scheduled/done),
                 scheduled_date, created_by, created_at
wish_likes     : wish_id, user_id                         ← 「わたしもやりたい」
memories       : id, wish_id, couple_id, date, place_name, lat, lng, rating, again
memory_notes   : memory_id, user_id, text, revealed       ← ふたりそれぞれのひとこと
photos         : id, couple_id, memory_id?, stop_id?, storage_path, width, height,
                 taken_at, caption, sort
plans          : id, wish_id, couple_id, title, start_date, days, share_token?
plan_stops     : id, plan_id, day, sort, time, name, lat, lng, todo, cost,
                 reserved, transport_to_next, minutes_to_next
plan_checklist : id, plan_id, text, checked_by, checked_at
notify_log     : id, couple_id, kind, sent_at              ← 送信数の上限管理用
```

- RLS（行単位の権限）: すべての表で「`couple_id` が自分の所属する空間であること」を条件にします。
- 写真: 非公開バケット `photos/{couple_id}/{photo_id}.webp` に保存し、表示するときだけ有効期限付きの URL を発行します。
- しおりの共有リンク: `share_token` を知っている人だけが読み取り専用で見られるようにします（Edge Function 経由）。

## 7. 無料枠で足りるかの見積もり

| 項目 | 無料枠の目安（2026年時点の公開情報。要再確認） | ふたりで使う場合 | 判定 |
|---|---|---|---|
| Supabase DB | 500MB | 文字データは数年使っても数MB | ◎ |
| Supabase Storage | 1GB | 写真1枚 約250KB＋サムネイル 約30KB → **約3,500枚** | ○（下の対策あり） |
| Supabase 転送量 | 月 5GB | サムネイルを中心に表示すれば十分 | ○ |
| Edge Functions | 月 50万回 | ログインと通知だけなので数百回 | ◎ |
| GitHub Pages | 月 100GB 転送 | 画面のファイルだけ | ◎ |
| LINE Messaging API | コミュニケーションプランは月の無料送信数に上限あり | 1日1回まとめて送る。アプリ側で上限をかける | ○ |

### 写真の容量が気になる場合の対策（段階的に）
1. 縮小して保存する（最初から実施）。「元の画質で残したい写真」は、スマホ本体や Google フォトに置いたまま、アルバムのリンクだけを貼れるようにします。
2. 使用量をアプリ内に表示し、80%を超えたらお知らせします。
3. それでも足りなくなったら、写真の保存先だけを Cloudflare R2（10GB 無料・カード登録が必要）に移せる作りにしておきます。

### Supabase 無料プランの注意点
- **1週間アクセスがないとプロジェクトが一時停止します。** 毎日開いていれば問題ありませんが、念のため GitHub Actions（無料）で週に数回、軽いアクセスをする仕組みを入れます。停止してもデータは消えず、管理画面から再開できます。
- 自動バックアップは無料プランに含まれないため、月に1回、データを JSON と ZIP で書き出す「バックアップ」ボタンを用意します。

## 8. セキュリティとプライバシー

- 権限チェック（RLS）は、**ふたり以外は一切読めない**ことを自動テストで確認します（3人目のテストユーザーでアクセスして拒否されることを確かめる）。
- 写真の保存先は非公開にし、URL は有効期限付きにします。
- 写真に含まれる位置情報（EXIF）は、縮小するときに取り除きます（場所は自分で入力した分だけ保存します）。
- 別れた場合や退会する場合に備えて、「空間から抜ける」「全データを書き出して削除する」機能を用意します。どちらか片方の操作で、写真が相手から急に消えないようにする配慮（たとえば30日の猶予期間）も入れます。
- LINE のチャネルシークレットと Supabase のサービスキーは、Edge Function の環境変数にだけ置き、GitHub には絶対に載せません。


## 10. リスクと対策

| リスク | 影響 | 対策 |
|---|---|---|
| LIFF と LINE ミニアプリの統合で仕様が変わる | 設定のやり直し | LIFF SDK を使う部分を1つのファイル（`line.js`）にまとめ、切り替えやすくする |
| LINE 内ブラウザの制限（動画の書き出し、ファイル選択など） | 一部の機能が動かない | 機能ごとに対応状況を確認し、使えない場合は「ブラウザで開く」（`liff.openWindow`）に誘導する |
| Supabase の一時停止・無料枠の変更 | しばらく使えない | 定期アクセス、月1回のバックアップ、保存先を差し替えやすい作り |
| 写真の容量不足 | 写真を追加できない | 縮小、容量の表示、R2 への移行手順を用意しておく |
| ほかのカップルにも公開したくなる | 無料枠や送信数を超える | 最初は「自分たち専用」と割り切る。公開する場合は、無料枠に収まる人数を見積もり直す |

## 11. 決めてほしいこと

着手する前に、次の4点を決めてもらえると進めやすくなります。

1. **使う人の範囲**: 自分たちふたり専用ですか？ それとも、ほかのカップルにも使ってもらいたいですか？（無料枠と、LINE の審査の要否が変わります）
2. **アプリの名前と雰囲気**: 例「ふたりのやりたいこと帳」「ふたり旅ノート」など。配色の好み（パステル・落ち着いた色など）。
3. **写真の量の想定**: 1回の思い出に何枚くらい残したいですか？（3,500枚で足りるかの確認です）
4. **リポジトリ**: 新しいリポジトリ（例: `futari-list`）を作るか、このリポジトリの `couple/` フォルダで作るか。

## 12. 着手前に確認すること

- LINE Developers: LINE ミニアプリチャネルで、未認証のまま自分たちが使えるか（公開範囲・必要な設定）。LIFF の統合時期の最新情報。
- LINE Messaging API: コミュニケーションプランの無料送信数と、`shareTargetPicker` で送ったメッセージが送信数に含まれないこと。
- Supabase: 無料プランの容量、一時停止の条件、LINE のような外部のログインからセッションを発行する方法の最新の推奨手順。
