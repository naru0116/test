# しよっか — ふたりのやりたいことリスト 開発計画書（第2版）

LINE の中で開いて使える、カップル向けの「やりたいことリスト ＋ 思い出アルバム ＋ 旅ルート風のしおり」アプリの計画です。
**作るのも使うのも0円**で、**ほかのカップルにも使ってもらう**ことを前提にしています。

> 作成: 2026-11-06 ／ 改訂: 2026-11-07（第2版：ほかのカップルにも公開する前提に変更、名前・配色・広める仕掛けを追加）
> LINE や各サービスの無料枠・規約は変わることがあるので、着手するときに「14. 着手前に確認すること」を見直してください。

---

## 0. 結論（第2版で変わったところ）

1. **LINE で一般公開できます。** 2024年11月28日から、LINE ミニアプリは**審査なしで「未認証ミニアプリ」として公開できる**ようになり、日本の個人も対象です。費用もかかりません。
   ただし未認証では、LINE からのお知らせ（サービスメッセージ）、ホーム画面へのショートカット、LINE 内検索への掲載が使えません。そのため、**広める手段は「ユーザーがトークや SNS でシェアすること」が中心**になります。
2. **写真の容量が一番の課題です。** 無料枠（1GB）は**全カップルの合計**です。第1版の「約3,500枚」は1組で使う場合の数字でした。多くのカップルで使うには、次の3つを組み合わせます。
   - 写真をもっと軽くする
   - 1組あたりの上限を決める
   - 写真の保存先を Cloudflare R2（10GB まで無料・転送料も無料）にする
   それでも**無料のまま使ってもらえるのは数百組まで**が目安です（→8章）。
3. **LINE のお知らせは使い方を変えます。** 公式アカウントから全員に送る方式は、無料の送信数の上限ですぐに足りなくなります。代わりに、次の無料の手段を使います。
   - ユーザー自身が相手に送るシェア（`shareTargetPicker`）
   - ユーザーが話しかけたときの返信（無料で送れます）
   - ホーム画面に追加したアプリの Web プッシュ通知
4. **名前は「しよっか」**をおすすめします。配色は夕焼けのデートをイメージした「マジックアワー」です（→2章）。

## 1. コンセプト

> **「ふたりの『しよっか』を、ぜんぶ叶えよう。」**

アプリでは、ひとつの「やりたいこと」が次のように育っていきます。

```
 💭 いつか          📝 計画中           📅 予定あり          ✨ 叶った！         📖 思い出
 「しよっか」  ──▶ しおりを作る ──▶ 日付が決まる ──▶ 写真・ひとこと ──▶ アルバム・
  を追加                                               を残す            スライドショー
```

ほかのアプリとの違いは次の4つです。

| | しよっか | よくあるカップルアプリ（Pairy など） | やりたいことリスト系（Wishly など） |
|---|---|---|---|
| インストール | **不要（LINE で開くだけ）** | 2人ともストアからインストール | 2人ともインストール |
| 主役 | **やりたいこと → 思い出** | チャット・記念日 | リスト |
| 計画 | **旅ルート風のしおり** | カレンダー | — |
| 思い出 | **ふたりのひとこと・スライドショー** | アルバム | 画像を添付 |

## 2. 名前と雰囲気

### 2-1. 名前の候補

| 候補 | 読み・意味 | 広まりやすさ | 判定 |
|---|---|---|---|
| **しよっか** | 「〇〇しよっか？」というカップルの口ぐせ。そのまま動詞のように使える（「それ、しよっかに入れとこ」） | ◎ 短くて言いやすく、会話の中で自然に広まる | **おすすめ** |
| やりたいね100 | SNS で定番の「カップルでやりたいこと100」とかけた名前 | ○ 検索に強いが、説明的 | 次点 |
| ふたりごと | 「ひとりごと」のもじり | ○ かわいいが、すでに使われている可能性が高い | — |
| 叶えっこ | 「叶える」＋「〜っこ（しあいっこ）」 | △ やや覚えにくい | — |

- 正式な表記は **「しよっか」**、英字は **`shiyokka`** とします（リポジトリ名、URL、LIFF アプリ名に使います）。
- 検索した範囲では、同じ名前のカップルアプリは見つかりませんでした。公開前に、特許庁の商標検索（J-PlatPat）と App Store・Google Play で、もう一度確認します。
- キャッチコピーの案:
  - 「ふたりの『しよっか』を、ぜんぶ叶えよう。」
  - 「やりたいね、を思い出に。」
- LINE の規約上、アプリ名に「LINE」という文字は入れられません（「しよっか」は問題ありません）。

### 2-2. 配色「マジックアワー」

夕焼けの空の、デートの帰り道のような色合いです。やわらかい印象にしつつ、路線図の線がはっきり見えるように、濃い色を差し色にしています。

| 役割 | ライト | ダーク | 使う場所 |
|---|---|---|---|
| メイン（夕焼けコーラル） | `#FF6F61` | `#FF8A7A` | ボタン、「しよっか」ボタン、ロゴ |
| サブ（ラベンダー） | `#9B8CFF` | `#B3A8FF` | 「ふたりの本命」バッジ、グラデーション |
| 達成（ミント） | `#2FB59A` | `#4FD1B5` | 「叶った！」、チェック |
| 予定（バター） | `#FFC857` | `#FFD27A` | 日付、予定ありのバッジ |
| 路線（夜空ネイビー） | `#2B2D42` | `#E8E6F0` | しおりの線路、文字 |
| 背景（クリーム） | `#FFF8F1` | `#1C1B29` | 画面の背景 |
| カード | `#FFFFFF` | `#272638` | カード、シート |

- ロゴとシェア用の画像には、コーラル → ラベンダーのグラデーション（夕焼け → 夜）を使います。
- 文字と背景の組み合わせは、読みやすさの基準（WCAG AA）を満たすように調整します。コーラルの上に白い文字を置くときは、太字・大きめの文字に限ります。
- 文字は丸みのある日本語フォント（例: Zen Maru Gothic・Google Fonts・無料）を、見出しにだけ使います。

## 3. LINE の中で動かす方法

### 3-1. 方式

| 方式 | 費用 | 審査 | 判定 |
|---|---|---|---|
| **LINE ミニアプリ（未認証）＋ LIFF SDK** | 無料 | **不要**。公開してすぐ誰でも使える | ◎ **採用** |
| LINE ミニアプリ（認証済み） | 無料 | 必要（1〜2週間の目安） | ○ 利用者が増えたら申請を検討 |
| ネイティブアプリ | Apple の開発者登録が年 12,980円前後 | 必要 | ✕ |

- 未認証ミニアプリでは、次の3つが使えません。これらは、認証済みミニアプリだけの機能です。
  - LINE からのお知らせ（サービスメッセージ）
  - ホーム画面へのショートカット
  - LINE 内検索への掲載
- 利用者が増えてきたら、認証を申請します（費用は無料）。そのとき審査に通りやすいように、最初から利用規約、プライバシーポリシー、問い合わせ先を用意しておきます。

### 3-2. 使う LINE の機能

| LINE の機能 | 何に使うか |
|---|---|
| `liff.init` / `liff.getIDToken` | 自動ログイン（パスワード不要） |
| `liff.getProfile` | アイコンと名前の表示 |
| `liff.shareTargetPicker` | **広める仕組みの中心**。相手への招待、しおりや思い出カード、達成率カードをトークに送る |
| `liff.permanentLink` | どの画面からでも、その画面を直接開くリンクを作る |
| LINE 公式アカウント「しよっか」 | 友だち追加してもらい、話しかけられたときに返信する（無料）。リッチメニューから「今日なにする？」「1年前の今日」を呼び出す |

LINE の外のブラウザや、ホーム画面に追加したアプリ（PWA）でも同じように使えるようにします。

## 4. 広める仕掛け（バズらせるための設計）

「インストール不要」と「LINE で送れる」を最大限に活かして、**使うほど自然にシェアされる**作りにします。

1. **テンプレート「カップルでやりたいこと100」**: 最初の画面で、定番のやりたいこと100個から選んで、すぐにリストを作れます。SNS で定番の話題なので、そのまま話題作りにもなります。季節ごとのテンプレート（クリスマス、夏休みなど）も用意します。
2. **達成率カード**: 「ふたりで 100個中 37個 叶えた💞」という縦長の画像を作り、Instagram のストーリーズ、TikTok、X に1タップでシェアできます。画像の隅に「しよっか」のロゴと QR コードを入れます。
3. **思い出スライドショーの縦動画**: 9:16 の動画として書き出し、リールや TikTok にそのまま投稿できます。顔を隠すスタンプも用意して、気軽に投稿できるようにします。
4. **しおりを友達に送る**: ほかのカップルや友達も、しおりを読み取り専用で開けます。開いた画面の下に「自分たちもしよっかを始める」ボタンを置きます。
5. **招待は LINE で一瞬**: 相手が開いたらすぐペアになり、インストールもアカウント登録も不要です。
6. **ふたりの本命**: ふたりとも「しよっか！」を押した項目がわかるので、会話のきっかけになります。こうした「話したくなる」体験を、シェアのきっかけにします。

> SNS に投稿する画像や動画に、本人たちの写真をどこまで入れるかは、投稿する人が選べるようにします。初期設定は「写真なし（イラストと文字だけ）」にして、うっかり公開してしまうことを防ぎます。

## 5. 機能一覧

優先度は ★3（最初に作る）〜 ★1（いつか）です。

### A. ふたりの空間（ペアリング） ★3
- 最初に開いた人が「ふたりの空間」を作り、`shareTargetPicker` で相手に招待を送ります。相手がそれを開くと、ペアが成立します。
- 付き合った日を登録し、「付き合って 〇〇日」を表示します。
- データはすべて「ふたりの空間」に所属し、ほかの人からは見えません。

### B. やりたいことリスト ★3
- 項目: タイトル、カテゴリ（🍽 グルメ／✈ 旅行／🎡 おでかけ／🏠 おうち／🎁 記念日／🎯 チャレンジ）、メモ、参考URL、場所、予算、いつ頃。
- **「しよっか！」ボタン**: 相手が追加した項目に反応できます。ふたりとも押した項目には「💞 ふたりの本命」バッジが付きます。
- 状態: 💭 いつか → 📝 計画中 → 📅 予定あり → ✨ 叶った。
- テンプレート「カップルでやりたいこと100」 ★3。
- ガチャ「今日なにする？」 ★2、達成率 ★3。

### C. 叶えた！→ 思い出 ★3
- 写真、日付、場所、満足度（⭐1〜5）、「また行きたい」。
- **ふたりそれぞれのひとこと**: 相手のひとことは、自分が書くまで見えません ★2。
- 写真はスマホの中で縮小し、位置情報（EXIF）を消してから保存します（→8章）。

### D. 思い出アルバム ★3
- タイムライン ★3、カレンダー表示 ★2、地図表示 ★2、「1年前の今日」 ★2。

### E. スライドショー ★2
- 写真がゆっくり拡大・移動する演出、テロップ、表紙とエンドロール。
- BGM は Web Audio で端末の中で合成するオリジナル曲にするので、著作権の心配がありません。
- **縦動画（9:16）での書き出し** ★2（4章の広める仕掛け）。LINE の中のブラウザで書き出せない場合は、通常のブラウザで開くよう案内します。

### F. 旅ルート風しおり ★2（綿密に計画するとき）
- **路線図ビュー**: 立ち寄る場所を「駅」、移動を「線路」として、1本の路線のように並べます。
  - 駅には時刻、やること、予約の有無、費用を表示します。
  - 線路には移動手段（🚃🚗🚶✈）と所要時間を表示します。
  - 複数日の旅行は「1日目線」「2日目線」のように路線を分け、宿を乗換駅として表示します。
  - 駅を長押ししてドラッグすると、順番を入れ替えられます。
- **地図ビュー**: Leaflet と OpenStreetMap で、番号付きのピンを線でつなぎます。
- **「Google マップで経路を見る」ボタン**: 駅を経由地にしたルートの URL を開くだけなので、API を使わず無料です。
- 持ち物チェックリスト（ふたりで共有）、予算の合計と割り勘 ★1。
- LINE で共有、読み取り専用のリンク、印刷用の A5 レイアウト ★1。
- **旅のあと**に各駅へ写真を追加すると、そのまま「ルート付きの旅の思い出」になります。

```
┌──────────────────────────┐
│ ✈ 金沢 1泊2日   🗺 地図 │
│ 1日目線 ━━━━━━━━━━━━━━  │
│  ◉ 09:12 金沢駅          │
│  ┃  🚌 バス 15分          │
│  ◉ 09:40 ひがし茶屋街    │
│  ┃  金箔ソフト食べる 💞   │
│  ┃  🚶 徒歩 10分          │
│  ◉ 11:30 近江町市場      │
│  ┃  海鮮丼（¥3,000）     │
│  ◎ 15:00 宿 ── 乗換 ──▶ │
│        2日目線へ          │
│ [Googleマップで経路] [共有]│

```

## 7. 技術構成（すべて無料）

```
  LINE アプリ ─ リンク ─▶ LIFF ブラウザ
                            │ ① 画面を読み込む
                            ▼
        Cloudflare Pages（HTML / CSS / JS・PWA）
                            │ ② LINE の ID トークン
                            ▼
  ┌──────────── Supabase（無料プラン）────────────┐
  │ Edge Function: line-login（LINE の検証 API で確認 → ログイン発行）│
  │ Postgres DB（リスト・思い出・しおり）＋ 行単位の権限（RLS） │
  │ Realtime（相手の追加・チェックをすぐ反映）            │
  │ Edge Function: photo-url（写真の保存先 URL を発行）     │
  └────────────────────────┬──────────────────────┘
                           ▼ ③ 写真のやり取り（有効期限付き URL）
            Cloudflare R2（写真・10GB まで無料・転送料無料）
```

### 7-1. それぞれを選んだ理由（第1版からの変更点を含む）

| 役割 | 採用 | 理由 |
|---|---|---|
| 画面の公開 | **Cloudflare Pages**（第1版は GitHub Pages） | 多くの人が使う公開サービスとして、転送量の上限を気にしなくてよい。GitHub と連携して、push するだけで公開できる。独自ドメインも無料で設定できる（ドメイン自体は有料なので、最初は `shiyokka.pages.dev` を使う） |
| データ・ログイン | **Supabase 無料プラン** | DB、ログイン（月5万人まで）、リアルタイム反映が無料。「ふたり以外は読めない」権限を SQL で確実に設定できる |
| 写真 | **Cloudflare R2**（第1版は Supabase Storage） | 10GB まで無料（Supabase は 1GB）。表示するときの転送料も無料なので、多くの人がアルバムを見ても費用がかからない |
| 地図 | Leaflet ＋ OpenStreetMap | API キー不要。地図画像の配信元は利用規約を守り、アクセスが増えたら無料で使える別の配信元に切り替える |
| 経路 | Google マップの URL を開くだけ | API を使わないので無料 |

> **Cloudflare R2 を使うには、クレジットカードの登録が必要です**（無料枠の中なら請求は0円です）。カードを登録したくない場合は、写真の保存先を Supabase Storage（1GB）にして始め、上限に近づいたら R2 に移ります。保存先は、`photo-url` 関数の中身を差し替えるだけで切り替えられる作りにします。

### 7-2. 無料枠を超えて請求されないための安全装置
- Supabase の無料プランは、上限に達すると**請求されずに止まる**仕組みなので、勝手に料金が発生しません。
- R2 は上限を超えると料金が発生するので、アプリ側で次の2つを入れます。
  - 全体の使用量が9GB を超えたら、新しい写真のアップロードを止め、管理者に知らせる
  - Cloudflare の請求アラート（例: 1円以上で通知）を設定する

### 7-3. コード
- 別班ボードゲームと同じく、**ビルド不要の ES モジュール（素の JavaScript）**で作ります。画面の量が増えたら Vite と TypeScript に移ります（GitHub Actions でビルドしても無料です）。
- 外部ライブラリ: `@line/liff`、`@supabase/supabase-js`、`leaflet`。
- 自動テスト: 状態の変化、権限（3人目のユーザーがデータを読めないこと）、しおりの時刻計算、写真の縮小。

## 8. 無料で何組まで使えるか

### 8-1. 写真を軽くする
| 種類 | 大きさ | 容量の目安 |
|---|---|---|
| 表示用 | 長い辺 1280px・WebP | 約150KB |
| サムネイル | 長い辺 320px・WebP | 約15KB |
| 合計 | | **1枚あたり約165KB** |

元の画質の写真は、スマホ本体や Google フォトに残しておいてもらいます。思い出カードには、外部アルバムへのリンクも貼れるようにします。

### 8-2. 1組あたりの無料の上限（案）
- **1組あたり写真300枚まで**（約50MB）。300枚は、1回の思い出に5枚ずつなら60回分です。
- 上限に近づいたら、写真の差し替えや削除を案内します。

### 8-3. 何組まで使えるか
| サービス | 無料枠 | 1組あたり | 使える組数の目安 |
|---|---|---|---|
| 写真（R2） | 10GB | 約50MB（上限まで使った場合） | **約200組**（平均100枚なら約600組） |
| 写真（Supabase Storage だけの場合） | 1GB | 同上 | 約20〜60組 |
| DB（Supabase） | 500MB | 文字データ約0.2MB | 約2,500組 |
| ログイン（Supabase） | 月5万人 | 2人 | 約2万5千組 |
| 画面の公開（Cloudflare Pages） | 転送量の上限なし（ビルド回数には上限あり） | — | 十分 |

**結論: 写真の容量で決まり、無料のままなら数百組までが目安です。**
本当にバズって利用者が増えた場合は、どこかで費用がかかります。そのときの選択肢は次の3つです（→13章の質問）。
- **A.** 新しい組の受け付けを止める（招待制にする）
- **B.** 写真の上限を増やす有料プランを用意する（例: 月300円で写真無制限）
- **C.** 広告を入れる（思い出を扱うアプリなので、雰囲気を損なわない形で）

## 9. データ設計（概要）

```
users          : id, line_user_id, display_name, avatar_url, created_at
couples        : id, name, anniversary_date, invite_code, photo_count, created_at
couple_members : couple_id, user_id, joined_at            ← 最大2人
wishes         : id, couple_id, title, category, memo, url, place_name, lat, lng,
                 budget, season, status, scheduled_date, template_id?, created_by
wish_likes     : wish_id, user_id                         ← 「しよっか！」
memories       : id, wish_id, couple_id, date, place_name, lat, lng, rating, again
memory_notes   : memory_id, user_id, text                 ← ふたりそれぞれのひとこと
photos         : id, couple_id, memory_id?, stop_id?, object_key, bytes, taken_at, caption
plans          : id, wish_id, couple_id, title, start_date, days, share_token?
plan_stops     : id, plan_id, day, sort, time, name, lat, lng, todo, cost, reserved,
                 transport_to_next, minutes_to_next
plan_checklist : id, plan_id, text, checked_by, checked_at
templates      : id, title, category, season              ← 「やりたいこと100」
push_subs      : user_id, endpoint, keys                  ← Web プッシュ通知
```

- **RLS（行単位の権限）**: すべての表で「`couple_id` が自分の所属するふたりの空間であること」を条件にします。
- 写真は R2 の `couples/{couple_id}/{photo_id}.webp` に置きます。表示とアップロードには、`photo-url` 関数が権限を確認したうえで発行する、有効期限付きの URL を使います。
- 相手のひとことは、自分が書くまで見えないようにします。この制御は、画面の表示ではなく DB の権限で行います。

## 10. 公開サービスとして必要なこと（法律・規約・安全）

ほかのカップルにも使ってもらうので、次のものを用意します。

| 項目 | 内容 |
|---|---|
| **利用規約** | 禁止事項、写真の権利は投稿者にあること、サービスの変更・終了、免責 |
| **プライバシーポリシー** | 取得する情報（LINE のユーザー ID・名前・アイコン、投稿した写真と文字）、利用目的、保存先（海外のサーバーを含む）、削除方法。個人情報保護法に対応する |
| **問い合わせ窓口** | フォームまたは公式アカウントのトーク |
| **データの書き出しと削除** | いつでも全データを ZIP で書き出せる。退会すると、データを削除する |
| **別れたとき** | どちらかが空間から抜けても、もう一方には30日間データが残り、その間に書き出せる |
| **出会いの機能は作らない** | ほかのカップルや知らない人を検索・表示する機能は作りません（いわゆる出会い系サイトの規制の対象にならないようにするため） |
| **年齢** | 利用規約で対象年齢を定める（例: 13歳以上、18歳未満は保護者の同意が必要） |
| **通報と削除** | 公開される共有リンク（しおりなど）に不適切な内容があった場合の通報と、リンクを無効にする機能 |
| **有料プランを始める場合** | 特定商取引法に基づく表示が必要（その時点で準備する） |

セキュリティの方針は次のとおりです。
- 権限（RLS）を自動テストで確認します。
- 写真は非公開にし、有効期限付きの URL でだけ表示します。
- 位置情報（EXIF）は削除します。
- LINE と Supabase、R2 の秘密の値は、サーバー側の環境変数にだけ置き、GitHub には載せません。

## 12. リスクと対策

| リスク | 対策 |
|---|---|
| バズって写真の無料枠を超える | 1組あたりの上限、全体で9GB を超えたらアップロードを停止、請求アラート、8章の A・B・C |
| LIFF と LINE ミニアプリの統合で仕様が変わる | LINE に関わる処理を `line.js` にまとめ、変更に対応しやすくする |
| LINE の中のブラウザの制限（動画の書き出しなど） | 機能ごとに確認し、使えない場合は通常のブラウザに誘導する |
| 無料枠や規約の変更 | 保存先を差し替えられる作り、データ書き出し機能 |
| 似た名前のアプリが出てくる | 公開前に商標と各ストアを確認する。必要なら商標の出願を検討する（有料） |
| 個人情報の漏えい | RLS の自動テスト、写真は非公開、秘密の値はサーバー側の環境変数だけに置く |

## 13. 決めてほしいこと（第2版）

1. **名前**: 「しよっか」で進めてよいですか？
2. **クレジットカードの登録**: 写真の保存先に Cloudflare R2 を使うため、カードの登録が必要です（無料枠の中なら0円）。登録してよいですか？ 登録しない場合は Supabase Storage（1GB・20〜60組まで）で始めます。
3. **利用者が増えたときの方針**: 8章の A（招待制で止める）、B（有料プラン）、C（広告）のうち、どれを考えておきますか？（今すぐ決めなくても大丈夫です。最初は A の仕組みだけ入れておきます）
4. **新しいリポジトリ**: GitHub で `shiyokka` という名前の**公開リポジトリ**を作成してください（このセッションからはリポジトリを新規作成できないため）。作成できたら教えてください。そのリポジトリをこのセッションに追加して、Phase 0 から作り始めます。
